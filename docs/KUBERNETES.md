# PharmaVigil on Kubernetes

<!-- How to install PharmaVigil on a Kubernetes cluster with the Helm charts and Strimzi (ADR-010), and what the
     kind end-to-end test in CI does. Same steps for a local kind cluster. -->

Not for clinical or regulatory use. Spontaneous reports do not prove that a drug caused a reaction. Synthetic
patients only.

## What is where

| Path | What |
|---|---|
| `ops/helm/pv-lib` | library chart: Deployment + Service template shared by every service |
| `ops/helm/<service>` | one chart per service and the UI (generated by `ops/helm/generate_service_charts.py`) |
| `ops/helm/oracle-free`, `ops/helm/artemis` | demo database and JMS broker (ephemeral) |
| `ops/helm/pharmavigil` | umbrella chart: everything above |
| `ops/k8s/strimzi` | Kafka (KRaft, one node) and the twelve pipeline topics for the Strimzi operator |
| `ops/kind` | kind cluster config and the values used by the CI test |

## Install (kind or any cluster)

Tools: Docker, kind v0.33.0 (or a cluster), kubectl, Helm 4.3.0.

```bash
# 1. Images (kind: load them into the cluster)
cd services && mvn -B package -DskipTests && cd ..
for s in pharmacy-service intake-gateway case-service signal-service submission-gateway; do
  docker build -f services/Dockerfile --build-arg SERVICE=$s -t pharmavigil/$s:0.1.0 services; done
docker build -t pharmavigil/frontend:0.1.0 frontend
kind create cluster --name pv --config ops/kind/cluster.yaml
for s in pharmacy-service intake-gateway case-service signal-service submission-gateway frontend; do
  kind load docker-image --name pv pharmavigil/$s:0.1.0; done

# 2. Kafka through Strimzi 0.51.0
kubectl create namespace pharmavigil
curl -fsSL https://github.com/strimzi/strimzi-kafka-operator/releases/download/0.51.0/strimzi-cluster-operator-0.51.0.yaml \
  | sed 's/namespace: .*/namespace: pharmavigil/' | kubectl create -n pharmavigil -f -
kubectl -n pharmavigil apply -f ops/k8s/strimzi/kafka.yaml
kubectl -n pharmavigil wait kafka/pv-kafka --for=condition=Ready --timeout=600s
kubectl -n pharmavigil apply -f ops/k8s/strimzi/topics.yaml

# 3. The Secret (values from your own password manager; never commit them)
kubectl -n pharmavigil create secret generic pharmavigil-secrets --from-env-file=<your file>
#    keys: ORACLE_PASSWORD, PV_DB_PASSWORD, JWT_SECRET (32+ chars), PV_DEMO_PASSWORD (12+ chars),
#          ARTEMIS_USER, ARTEMIS_PASSWORD

# 4. The chart
for c in pharmacy-service intake-gateway case-service signal-service submission-gateway frontend pharmavigil; do
  helm dependency build ops/helm/$c; done
helm install pv ops/helm/pharmavigil -n pharmavigil -f ops/kind/values-kind.yaml --wait --timeout 20m
```

The UI is then on http://127.0.0.1:8080 (kind maps NodePort 30080 there). Sign in as `pharmacist` or `reviewer`
with `PV_DEMO_PASSWORD`.

## Optional mounts

`case-service` reads models from `PV_MODEL_DIR` and the E2B(R3) schemas from `PV_E2B_XSD_DIR`; both are empty in
the charts, so cases go to manual coding and nothing can be submitted. To use them, set the env value and add a
volume, for example in your values file:

```yaml
case-service:
  env: {PV_MODEL_DIR: /models}
  volumes: [{name: models, persistentVolumeClaim: {claimName: pv-models}}]
  volumeMounts: [{name: models, mountPath: /models, readOnly: true}]
```

## The CI test

`.github/workflows/kind-e2e.yml` runs the steps above on every pull request with random throwaway secrets and
then the Playwright smoke test (`frontend/e2e/smoke.spec.ts`). On failure it prints pod state, events and the
last 200 log lines of every pod.

Checked locally in the build container: `helm lint` on all nine charts (0 failures) and `helm template` of the
umbrella chart (8 Deployments, 8 Services, 1 ConfigMap). The cluster run itself happens only in CI, because this
container cannot pull the Strimzi images from quay.io.
